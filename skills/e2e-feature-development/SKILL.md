# E2E 풀스택 개발 지침 (E2E Full-Stack Development Strategy)

이 스킬은 새로운 기능을 처음부터 끝까지 풀스택으로 개발할 때 에이전트가 준수해야 하는 **필수 작업 순서**입니다.

## 1. 화면 분석 및 기존 자산 검색 (중요)
- 현재 개발하려는 프론트엔드 화면의 코드를 분석하여 필요한 API 데이터 구조를 도출합니다.
- **반드시** 프로젝트의 API 명세서(예: openapi.yaml 등)와 DB 스키마 스냅샷, 최신 DB 마이그레이션 스크립트들을 확인해 이미 동일한 API나 테이블이 있는지 파악하여 중복 생성을 방지합니다.
- 새로운 프론트엔드 UI 컴포넌트나 로직을 만들기 전에 반드시 공통 컴포넌트/유틸리티 계층(예: shared/ 폴더 등)을 먼저 검색하여 바퀴의 재발명을 방지합니다.

## 2. API 및 DB 설계 (Flyway 타임스탬프 버전 관리)
- 검색 결과를 바탕으로 API 명세서를 증분 업데이트합니다.
- DB의 실제 변경은 반드시 지정된 마이그레이션 폴더(예: Flyway의 db/migration/)에 새로운 마이그레이션 스크립트를 생성하여 처리합니다. 충돌 방지를 위해 타임스탬프 기반의 파일명(`VYYYYMMDDHHMMSS__description.sql`)을 사용하는 것을 권장합니다.
- 다른 에이전트들이 현재 DB 구조를 한눈에 파악할 수 있도록 통합 DB 스키마 스냅샷 파일이 있다면 방금 수정한 내용에 맞게 최신 상태로 덮어씁니다.

## 3. 백엔드 구현 (TDD 방식) 및 연동
- 설계된 스펙에 맞추어 백엔드 애플리케이션에 **먼저 실패하는 테스트 코드(Unit/Integration Test)를 작성**합니다.
- 이 테스트가 모두 통과할 때까지 컨트롤러와 서비스를 구현 및 수정하여 로컬 개발 환경(Local Loop)에서 1차로 에러를 모두 해결합니다.
- **주의:** 타 도메인의 데이터를 조회/수정해야 할 경우 절대 해당 도메인의 Mapper/Repository를 직접 주입받지 말고 반드시 해당 도메인의 Service를 호출하도록 구현합니다.
- 로컬 테스트가 통과하면, 프론트엔드 화면에 API 연동 코드를 추가합니다.

## 부록: 풀스택 수직 분할(Vertical Slice) 책임 범위
개발 시 아래의 범위를 한 번에 완결성 있게 End-to-End로 책임집니다.
- **프론트엔드**: 도메인 모델, 사용자 기능, 라우팅 화면 (예: FSD 아키텍처의 entities, features, pages 등)
- **백엔드**: 해당 도메인의 API 라우터/컨트롤러, 비즈니스 로직(Service), 데이터 영속성 계층(Repository/Mapper)
- **DB 및 명세**: API 명세서, DB 스키마 스냅샷, DB 마이그레이션 파일
